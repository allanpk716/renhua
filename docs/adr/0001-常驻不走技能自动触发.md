# 常驻不走技能自动触发

日期：2026-09-24 · 状态：accepted

用户希望"安装后不用说就生效"（常驻语义）。我们决定：renhua 技能本体保持手动触发（description 写窄），常驻需求用确定性配置实现——给公开用户的 README 常驻片段（贴入其 `~/.claude/CLAUDE.md`）和作者本人的全局常驻块；不改宽技能 description、不走模型自判自动调用。

为什么：技能 description 自动触发是概率性行为——长会话会忘、弱模型更差、误伤面大（"帮我改写这段代码"是重构、"公文/论文"不该套大白话）；CLAUDE.md 家族文件每会话确定性加载，说删就停。2026-09-24 共存实验复审（codex+kimi 两轮）进一步确认：模型在两套规则冲突时会按"来源/优先级"自行裁决且两个模型答案相反（S7 证据），常驻块的效力来自确定性加载而非模型自觉。

## Considered Options

- **改宽 description 走模型自判**：否——概率性触发，不可靠；且会丢掉"把这段改成人话"自然语言显式触发路径之外的所有确定性。
- **加 `disable-model-invocation: true` 硬开关**：否——加了之后自然语言显式请求（"说人话/改写"）也无法调用技能，公开用户损失 prose 触发路径；description 写窄的软约束已够。
- **output style / Stop 钩子**（三档自动化中的二、三档）：备选未启用——与 concise 等风格互斥；Stop 钩子最强硬但有误伤白名单与重试上限问题（见 DEVLOG §5）。

## Consequences

- 三处同源派生：全局常驻块、README 片段、SKILL.md 边界情况，均以 `rules.md` 为单一事实源，改规则先改 rules.md 再派生（防漂移，DEVLOG §7 教训）。
- 载体验收（2026-09-24 落地时执行）：C 条件实验用 `CLAUDE.local.md` 载体，最终载体效力经路径 a 最小验收确认（S7+S1 重跑，见 DEVLOG §8）；README 片段与全局块同属 CLAUDE.md 家族（每会话加载），由同类机制覆盖。
- 适用范围：共存验证在 Windows 10/Git Bash、i-have-adhd 纯技能形态（插件 hooks 未测）、单轮采样、含本人全局配置的会话环境下完成；跨环境/插件形态/长期稳定性未验证。
